# Reporting a security vulnerability

Please report suspected vulnerabilities privately to **support@craftsky.social**. Do not open a public issue or PR containing exploit details, credentials, or personal data.

Include the affected component and version or commit, the suspected impact, and minimal reproduction steps using synthetic data or an account you control. If you have a possible fix, describe it privately first. Never send live secrets; redact tokens, OAuth callback parameters, and private payloads.

The maintainer will assess the report, coordinate a fix where needed, and agree on public disclosure with the reporter. There is no guaranteed response time or bug bounty. The inbox is checked on UK business days and is not an emergency-response service.

CraftSky is in active development. Report issues affecting current `main` or the deployed service; there is no separately maintained security-support branch for older releases. A report about an older version is still useful if the issue may remain present.

Keep investigation limited to systems and test accounts you are authorized to use. Avoid accessing other people's data or disrupting the service. Ordinary bugs without a security impact belong in the [public issue tracker](https://github.com/Zambrella/craftsky/issues/new/choose).
