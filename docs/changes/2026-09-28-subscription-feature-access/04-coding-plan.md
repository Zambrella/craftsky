## 2. Implementation Strategy

Reuse `subscriptions.Store.SelfAccess` as the authority for the authenticated DID and extract one shared tier/predicate and batch-access contract for read projections. Wire authorization at server-backed capability boundaries; Flutter supplies discoverability and account-scoped state, never authorization. Make existing public business classification and customisation projections depend on current effective tier. Preserve private folder/customisation data through lapse, but clear active pin rows only on an effective Plus-or-higher → Free transition. A scheduled worker must check effective access at its final guarded PDS command boundary, with a serialization fence against concurrent access-loss commits.

Do **not** interpret RevenueCat events as feature grants, use billing-owner identity as a beneficiary, or add paid rank/reach. Remove the testing-only account-type selector, `PUT /v1/profiles/me/account-type` and unused `craftsky_account_types` table; public `accountType` remains a read-only response value derived from a Business assignment. Hide all Business owner options/pages and deny Business owner-management API reads/writes/deletes without Business access. Public views of a *licensed* business remain available to all eligible visitors. Business PDS records remain authored and indexed even while CraftSky hides them during lapse.

## 5. Services, Interfaces, And Data Flow

**Authoritative tier and table removal.** `subscriptions.ProjectSelfAccess` already maps an assigned but inactive licence to Free. Add a narrow `AllowsPlus/AllowsBusiness` policy and batch `EffectiveTiers(ctx, dids)` (illustrative) to the subscription store, applying the same environment, anomaly, assignment, and `gives_access` conditions as `SelfAccess`. Read-only profile/account-type hydrators receive one batch reader instead of querying per actor. For Business SQL read paths, use one bounded, set-based active-assignment predicate with the same environment parameter in `business.Store` rather than joining `craftsky_account_types`; keep membership, block, moderation and timing predicates untouched. Once all reads and deletion/lifecycle references have moved, drop the testing-only table with a new forward migration; update `terminal_inventory.go` and account-deletion participants so cleanup no longer queries it. Verify both migration directions and runtime behavior with IT-012. No query may take a caller-supplied DID as authority for a protected mutation.

```text
EffectiveTier(ctx, authenticatedDID) -> Free | Plus | Business | error
EffectiveTiers(ctx, visibleDIDs[]) -> map[DID]Tier | error
RequirePlus(ctx, authenticatedDID) / RequireBusiness(...) -> permitted | paid-access error
```

**Route policy.** Apply a paid-capability wrapper after authentication/current-member middleware and before any side effect, preserving standard `{error, message, requestId}` and camelCase JSON. Guard scheduled create/update/manual publication and scheduled media staging where needed; retain scheduled owner list/get and safe deletion so the required subscription error remains visible. Guard folder creation/rename/delete/assignment but keep ordinary save/unsave and `GET /v1/saved-posts` free. If a Free save request carries `folderId`, reject the folder assignment without losing ordinary saved-post functionality; do not silently assign it. Guard pin PUT/DELETE and private follower-growth GET. Guard customisation PUT while allowing public reads with defaults. Guard **all Business owner-management** GET/POST/PUT/DELETE operations (including `GET /v1/events`, own event detail as management view, declaration/event deletes). For shared public event-detail GET, branch on caller==owner: unlicensed owner cannot retrieve management content; public visitors can read only if the business owner is licensed and content is otherwise eligible. Keep public profile/event reads of licensed businesses available to eligible visitors regardless of visitor tier. Retire `PUT /v1/profiles/me/account-type` from registration/policy; retain read-only `accountType` in responses.

**Business lapse (resolved DR-004).** `GET /v1/events` is a Business owner-management view and unavailable during lapse. `GET /v1/events/{did}/{rkey}` is shared: an unlicensed owner must not gain a management bypass by requesting their own record; a visitor can still see an eligible event when its owner is licensed. Public profile/event projections suppress unlicensed owner's details for **all** CraftSky viewers including the owner. Block unlicensed declaration/event edits and deletes through AppView while retaining indexed and PDS records; restoration re-enables the normal management paths and public serving. The subscription page in Settings stays reachable. No extra owner-only recovery API is in scope and no PDS deletion occurs automatically.

**Pin and folder transition.** Compare the *previous and next effective tier of each affected assigned DID* during snapshot reconciliation and assignment changes. On Plus/Business → Free, clear both pin selections in the same ordered transactional lifecycle (or a synchronously fenced idempotent cleanup that completes before public reads), never on mere `will_not_renew`. Protect concurrent pin mutation against that transition so a late pin cannot be committed after cleanup. Free reads of `GET /v1/saved-posts` use the existing all-saved scope/pagination, with folder IDs omitted from Free response presentation; stored folder IDs remain untouched and reappear after restoration. Folder-management GET is not required to feed the Free flat list. Re-check any embedded `viewerSavedFolderId` values so private folder identity does not leak through unrelated post responses during lapse.

**Scheduled worker (DR-003).** The worker currently claims in `Worker.ProcessBatch`, then `PublicationProcessor.Process` validates/freezes/selects session and calls `ExecuteAppend` inside `WithGuardedCommands`/`AcquirePublishingEffect`. Add a subscription check before admitting due work and, critically, at the last guarded point before `ExecuteAppend` (after media work); if absent, record a dedicated safe `subscription_required` needs-attention reason with no PDS command and no automatic retry. For an already claimed job, serialize this final check + external append with any access-loss commit for its DID using a domain-separated per-DID advisory fence, following existing owner-effect lock ordering. Acquire transition locks for all affected DIDs in deterministic order **before** updating entitlement-bearing rows; never wait for those locks while holding an incompatible owner-effect fence. This provides an ordering: if access loss commits first, append is denied; if append has already entered its effect fence, the transition cannot commit until it settles. The implementation must verify lock order/timeouts across `ApplySnapshot`, reassignment, and worker paths with IT-011, and report any uncovered external-commit window before proceeding. Pending future items remain owner-visible with a non-terminal subscription notice; if access returns before due, normal schedule remains; missed items stay needs-attention until owner action. Do not rewrite historical published posts.

## 6. State, Providers, Controllers, Or DI

- Flutter provider graph: active `SessionRegistry`/lease → existing `subscriptionAccessProvider(lease)` → small feature gate projection (Free/Plus/Business/loading/error) → settings row, composer, saved-post, pin action and Business section. Reuse generated Riverpod `@riverpod Future<SubscriptionAccess>` and account-boundary invalidation; a pure gate projector or `Provider` suffices for eligibility, no new billing controller or RevenueCat identity changes. Pending/error access fails closed for mutations and offers retry instead of presenting the member as definitively Free.
- Keep `savedPostsProvider` keyed to active account and an all-saved `SavedPostScope` in Free mode; do not watch `savedPostFoldersProvider` merely to render Free flat view. On access refresh or account switch invalidate the affected saved/folder/pin/profile/growth providers and avoid optimistic state from another DID. Use the existing subscription invalidation pattern for purchase/assignment/restoration.
- Retire `accountTypeControllerProvider` and mutation-only `BusinessApiClient.updateAccountType`; remove its generated Riverpod provider through the normal generator workflow only when implementation begins. `SettingsPage` and `AccountPage` consume authoritative `Profile.accountType` for read-only display, never a local override. Keep existing conditional Business settings section **hidden** unless `subscriptionAccessProvider` confirms effective Business access. Protect typed deep links to `BusinessEventsRoute`/`BusinessProductsRoute` and owner editor pages; waiting/error access does not open them. No Business upgrade entry is shown inside the hidden section; the ordinary subscription page stays available in Settings. The backend independently denies unlicensed owner routes (AT-008/IT-007).
- AppView DI: pass the same subscription-access reader from `app/deps_subscriptions.go` through `routes_adapter.go` into route bundles and public hydrators. Supply it to the publication processor through `app/deps_scheduled.go`. Batch projections remain bounded and avoid N+1 lookups.

```text
active lease ── subscriptionAccessProvider(lease) ── feature gate ── widgets
                     │                               └── locked dialog → SubscriptionsRoute
AppView session DID ── subscriptions.Store ── route guard / batch public projection
                                     └── reconciled transition → pin cleanup
                                     └── fenced scheduled effect check → PDS command
```

## 7. UI, Widgets, Routes, Or User-Facing Surfaces

- **Plus:** Labelled lock overlay on existing schedule affordances (composer and scheduled-post entry), saved-folder create/manage/move actions, profile colour/background settings, post pin menu and follower-growth settings. Free activation displays one localized, feature-specific subscription-required dialog with a learn-more CTA to existing `SubscriptionsRoute`; action itself does not execute. Plus/Business retain ordinary action. UI lock presentation does not replace server checks.
- **Business:** Business section and every owner Business menu/editor option are hidden for Free/Plus or uncertain access; only the active DID with confirmed effective Business access may enter Business owner routes. No per-item Plus-style overlay or Business-section upsell is required. Remove the account-type `SegmentedButton` and `accountTypeController` interaction entirely; retain public Business label based on effective tier. Account switches/refresh re-evaluate before displaying business tools. Visitors of any tier can still read a licensed business's eligible public content.
- **On lapse:** Saved posts render in one flat collection; folder controls are locked and folder membership stays private/durable. Profile identity uses standard default colour/background; previously selected choices remain stored. Public pinned-card decoration and promotion disappear after pin cleanup. Scheduled-post rows show a subscription-needed notice while pending without access and safe error when blocked at due time. Business declaration/events and owner-management routes disappear from CraftSky serving until Business access returns; PDS records remain unchanged.
- **Routing:** No new paid purchase route. Remove method/policy for account-type PUT; existing subscription page under `/profile/settings/subscriptions` remains. Prevent unauthorized Business deep links in Flutter and deny Business owner API routes in AppView; do not block visitor public reads of a licensed business. Preserve authenticated `/v1/` middleware and error envelope on paid failures. The removed endpoint must be unavailable even for an active Business subscriber (AT-003/IT-006).

## 10. Sequencing And Guardrails

- First TDD step: write UT-001 for an assigned Plus DID, an assigned Business DID and a cancelled-but-accessible subscription, then implement the smallest reusable DID-scoped access policy; follow with IT-001 direct-API proof.
- Dependencies: Shared tier predicate and batch read before server guards/public projections; replace all legacy table reads/cleanup before migrating it away; transition semantics before pin cleanup/scheduled worker; account identity and provider invalidation before Flutter lock UI. Update older tests that encoded the testing-only free business switch to use licensed fixtures; retain moderation/ownership assertions.
- Guardrails: No plain RevenueCat `CustomerInfo` authorization; no synchronous external provider call per request. No PDS deletion on lapse or lexicon change. Drop only the unused testing-only account-type table after eliminating live dependencies; do not drop business source/index tables. Do not gate public visitor reads of licensed businesses or ordinary saved-post GETs; distinguish visitor from owner management. On scheduling, use existing guarded commands/idempotency and a common lock order rather than assuming the claim is still valid.
- Out of scope: Price/catalog changes, native purchase/restore changes, paid reach, reinstating profile border, generic new billing tiers and web checkout. Keep first-party normal post/save and owner deletion behaviors intact.
