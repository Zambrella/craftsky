# UI Polish Notes: Flutter Business Profiles

## Summary

This pass gives business profiles a business-first information hierarchy and brings profile, product, and event editing surfaces into the existing CraftSky visual language. It reuses the shared theme, spacing tokens, inputs, dialogs, responsive modal navigation, and primary button treatment while preserving validation, conflict, and account-boundary behavior. The existing unsaved-work confirmation now also covers incomplete dirty event drafts.

## Scope Guardrails

- Requirement behavior changed: Yes, for the requested event presentation, dirty-close behavior, deferred event-image upload timing, and immediate product persistence
- Business logic changed: Yes, event images are now prepared locally on selection and uploaded immediately before the event mutation; product mutations now persist the complete declaration immediately instead of staging a manager-level batch
- APIs, data models, migrations, permissions, or dependencies changed: Yes, `l10n_currencies` is now a direct Flutter dependency for localized ISO currency labels
- Notes: Tab ordering, initial presentation, and event presentation changed intentionally. The existing discard decision now also covers incomplete dirty event drafts, and the existing end-after-start rule is now explained beside End. Event mutation payloads, validation rules, conflict recovery, account fencing, and route admission remain unchanged; only blob-upload timing moved to Save. Product storage remains one ordered declaration array with whole-record `If-Match` writes. Hidden all-day values are preserved on save.
